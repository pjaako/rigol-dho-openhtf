# SPEC: capture conditions as readable YAML files

Decision (made by the project owner's boss): capture conditions are written as YAML with unit strings,
readable by an engineer who does not know SCPI. The prototype in `proto/` works; turn it into production code.

```yaml
timebase: 1 ms/div
ch1:
  scale: 1 V/div
  offset: -1.5 V
  coupling: DC
trigger:
  source: ch1
  level: 1.5 V
  slope: rising
  mode: normal
memory: 1M
```

**The real oscilloscope is NOT available to you.** Do not open `192.0.2.10` or any VISA resource, do not run
`bench_usb.py` or `example_test.py` without `--fake`. Read `AGENTS.md`, `README.md`, `SPEC-setup.md`, the

## 1. `capture.py` (new, replaces `proto/capture.py` and `proto/capture_yaml.py`)

One module, standard library plus PyYAML (imported inside the functions that need it). It contains:

- The typed model from `proto/capture.py`: quantities `Volts`, `Seconds`, `PerDiv[...]`, unit constants
  `V mV s ms us ns div`, frozen keyword-only dataclasses `Channel`, `Edge`, `Capture`, runtime validation in
  `__post_init__`, and `Capture.to_scpi()`. Keep the Python spelling working
  (`Capture(timebase=1 * ms / div, ...)`); it is the API for code, YAML is the API for people.
  Fix what `mypy --strict capture.py` reports (mypy is not installed in the project venv; reason about the
  annotations, the project owner will run it).
- **One source of truth.** The allowed keys, the choices (`coupling`, `probe`, `slope`, `mode`, `source`,
  `memory`), the units and which fields are required must be defined once, as data, and used by the parser,
  by `to_scpi()` where relevant, and by the schema generator. Adding a coupling mode must be a one-line change.
- `parse_capture(data: dict, source: str = 'capture') -> Capture` and `load_capture(path) -> Capture`.
- `capture_schema() -> dict`: the JSON Schema (draft 2020-12) generated from the same definitions.
  `additionalProperties: false` everywhere except `extra`. Every property gets a `description` with an
  example, because editors show it as a tooltip.
- Command line: `python capture.py schema` prints the schema as JSON (indent 2, trailing newline);
  `python capture.py check FILE...` loads each file, prints `OK file` or the problems, exits 1 if any failed.

### Parsing rules

- Quantities are strings `<number> <prefix><unit>` with optional spaces: prefixes `m`, `u`, `µ`, `n`, `k`
  (and none); units `V` and `s`; `/div` where the field is per division. A bare number (`offset: -1.5`) is
  an error: the unit is mandatory.
- `memory` accepts `auto 1k 10k 100k 1M 10M 25M`. YAML may hand you an int for something like `memory: 10000`;
  that is an error with the message naming the accepted spellings.
- YAML 1.1 turns `on off yes no` into booleans. If a boolean arrives where a string choice is expected, say so
  in the message (`... YAML read this as a boolean; quote it`).
- `extra` is a mapping of raw SCPI header to value, passed through to `to_scpi()` last.
- **Duplicate keys are an error** (PyYAML silently keeps the last one): use a loader that rejects them.
- The trigger source must be a described channel.
- **Report every problem in one pass**, never stop at the first. Raise `CaptureError(ValueError)` whose
  message lists them, one per line, each as `<file>:<line>: <key path>: <what is wrong and what is expected>`.
  Line numbers are 1-based and point at the offending key or value (use PyYAML's node marks,
  `yaml.compose`). For an unknown key suggest the closest allowed key (`difflib`).
  `CaptureError.problems` is the list of those strings.

## 2. Plug

## 4. Editors: PyCharm and VS Code

Both must validate and auto-complete `captures/*.yaml` against `capture.schema.json`.

- First two lines of every capture file:
  ```yaml
  # yaml-language-server: $schema=../capture.schema.json
  # $schema: ../capture.schema.json
  ```
  The first is read by VS Code (Red Hat YAML extension), the second by JetBrains IDEs.
- `.vscode/settings.json` with `"yaml.schemas": {"./capture.schema.json": "captures/*.yaml"}`.
- PyCharm project mappings live in `.idea/`, which is not committed here. Document the manual path in the
  README: Settings > Languages & Frameworks > Schemas and DTDs > JSON Schema Mappings, schema file
  `capture.schema.json`, file path pattern `captures/*.yaml`, schema version 2020-12.
- You cannot test the editors. Say so in your report; do not claim they work.
